# Contributing

Thank you for helping with chunkdb.
This file applies to every repository in the organization.

If a repository has its own `CONTRIBUTING.md`, read it too.
Its rules for building, testing, and commit messages take precedence for that repository.
Today `chunkdb` and `chunkdb-js` have one.

## Repositories

- [chunkdb](https://github.com/chunkdb/chunkdb): the storage engine.
- [chunkdb-go](https://github.com/chunkdb/chunkdb-go): the Go client.
- [chunkdb-js](https://github.com/chunkdb/chunkdb-js): the Node.js and TypeScript client.
- [chunk-cli](https://github.com/chunkdb/chunk-cli): the command-line client.

## Before you start

- Open an issue first for any larger change, and wait for agreement on the approach.
- Small fixes, such as typos and obvious bugs, can go straight to a pull request.
- Search existing issues before opening a new one.
- Report security problems privately, as described in [SECURITY.md](SECURITY.md).

## Pull requests

- Keep one topic per pull request.
- Link the issue it closes.
- Add or update tests when behavior changes.
- Run the repository's checks before you push.
- Update the docs in the same pull request when behavior that users see changes.

## Documentation

- Write for the reader of that document.
- Keep user docs free of maintainer and release details.
- Use short sentences, one sentence per line.
- Do not add marketing language, unsupported claims, or promises about future work.
- Prefer short examples that can be copied and run.

## Conduct

All participation follows the [Code of Conduct](CODE_OF_CONDUCT.md).
